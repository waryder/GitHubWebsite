Inventory Processing → Node View → Inventory Sorter → Source Inventories

Source Inventories

Check inventories from which matching whole slot records may be moved. Available rows follow the loaded inventory roster: Exosuit, Container 1–10, Freighter, Fish Platform, Fish Bait Box, Cooking Ingredients, then starships. Names come from loaded data; missing names use No name provided. The organizer omits identifiable empty ship slots and invalid inventory entries.

Inventory Processing → Node View → Inventory Sorter → Target Inventories

Target Inventories

Check receiving inventories. Each target has its own category dropdown. Existing contents remain but positions are compacted first; the sorter resets each processed target to a 120-cell grid. Identical source/target inventories are skipped.

Inventory Processing → Node View → Inventory Sorter → Use All Unselected Storage Containers For Overflow

Use All Unselected Storage Containers For Overflow

Checked initially. The current implementation scans backward from Storage Container 10 and adds unchecked targets until it meets the first checked container, then stops. Do not assume the label guarantees that every unchecked container is used. Added overflow targets accept all six categories.

↑ This page’s hierarchy

Inventory Processing → Node View → Inventory Sorter → Execute Sort

Execute Sort

Runs immediately against app-model data; there is no Review/Apply stage. Saves sorter choices and normally reports Inventory has been sorted! before closing. Source/target/category choices must be meaningful. The legacy caller can still show its completion notice after an internal validation warning, so inspect the actual result rather than relying only on that notice. File saving remains separate.

Inventory Processing → Node View → Inventory Organizer → Gather from these sources

Gather from these sources

Choose inventories whose whole saved slot/stack records may be gathered. Parts means records, not individual quantity units: the organizer does not split/merge stacks or change amounts. Available rows follow the loaded inventory roster: Exosuit, Container 1–10, Freighter, Fish Platform, Fish Bait Box, Cooking Ingredients, then starships. Names come from loaded data; missing names use No name provided. The organizer omits identifiable empty ship slots and invalid inventory entries.

Inventory Processing → Node View → Inventory Organizer → Optional

Optional

Two independent settings control overflow and destination expansion.

Inventory Processing → Node View → Inventory Organizer → Optional → Overflow: if destination is full, overflow to other 'Container' type storages.

Overflow: if destination is full, overflow to other 'Container' type storages.

Uses available containers unassigned to every category, working backward from Container 10 and excluding the record’s source. With no suitable space the record stays where it started. Checked by default unless saved preferences say otherwise.

↑ This page’s hierarchy

Inventory Processing → Node View → Inventory Organizer → Optional → Expand all Destination storages to 120 cells.

Expand all Destination storages to 120 cells.

Expands every assigned destination, even if no record moves to it. With expansion enabled, an overflow container also expands when it receives records. With expansion off, existing unoccupied valid cells determine capacity and no destination is automatically expanded. Checked by default unless saved preferences say otherwise.

Inventory Processing → Node View → Inventory Organizer → Review Summary

Review Summary

Read-only proposal display. Before review it shows current source/category routes without move counts. After review it summarizes the proposal; the current renderer may omit overflow-only or retained-only rows, so absence of a row is not a complete inventory audit.

↑ This page’s hierarchy

Inventory Processing → Node View → Inventory Organizer → Review Moves

Review Moves

Creates a private proposal without publishing inventory changes. Disabled when no sources are selected and expansion is off. Requires synchronized Raw JSON in every tab and valid loaded context. Any source, route or option change invalidates this review.

↑ This page’s hierarchy

Inventory Processing → Node View → Inventory Organizer → Apply to app data

Apply to app data

Enabled only after review proposes a change. Applies the exact candidate, refreshes app views, marks modified data and closes. Rejects changed source identity or data since review. This is not File Save.

Inventory tree

Expand an inventory to inspect its fields and stored slot records. Inventory drag/drop is not enabled by the initial tree configuration.

Inventory Processing → Node View → Inventory tree → Right-button drag selection → Delete N Nodes

Right-button drag selection → Delete N Nodes

The shared right-button range-selection handler can expose Delete N Nodes even on this tab, although its ordinary right-click menu has no Delete Node item. Confirmation removes the selected structure through the generic handler. This is structural deletion, not the category-based Organizer; do not use it casually on inventory fields.

Inventory Processing → Node View → Right-click menu

Right-click menu

Inventory-specific commands appear on eligible inventory records.

Inventory Processing → Node View → Right-click menu → Backup this Inventory

Backup this Inventory

Writes the selected inventory’s Node View JSON to a chosen *.nms_inventory.json file. Its Name supplies the proposed filename, or default if unnamed. This exports one inventory record, not the whole save.

↑ This page’s hierarchy

Inventory Processing → Node View → Right-click menu → Replace Items from Backup

Replace Items from Backup

Opens Replace Inventory Contents and reads a selected *.nms_inventory.json file. Replaces only the selected inventory’s Slots from the backup, not its whole record. If its ValidSlotIndices has fewer than 120 entries, the helper expands it to the 120-cell grid first. This edits app data and is not a full-save restore. Review the selected target and replacement contents before saving.

Toggle Expansion 2 Levels

Highlight In Text Box

Inventory Processing → Raw JSON

Raw JSON

Contains the inventory data exposed by this tab.

Inventory Processing → Raw JSON → Synched to Node View — status indicator

Synched to Node View — status indicator

Shows whether the app has marked this tab’s Raw JSON and Node View synchronized. Green means synchronized; red means synchronization is needed. This does not mean the live save has been written.

↑ This page’s hierarchy

Inventory Processing → Raw JSON → Sync to Node View

Sync to Node View

Parses this tab’s current Raw JSON, updates the app’s model, and rebuilds the Node View. Use after direct text edits; invalid JSON must be corrected before it can be used as structured data.

↑ This page’s hierarchy

Inventory Processing → Raw JSON → Pretty Print

Pretty Print

Parses the current text into the model, reloads indented JSON, and rebuilds the Node View. It therefore applies parseable text edits as well as formatting them.

↑ This page’s hierarchy

Inventory Processing → Raw JSON → JSON text editor

JSON text editor

Displays this tab’s inventory-view data. You can edit the JSON directly. Line numbers identify text lines; the current line is highlighted. Text is not line-wrapped, so long lines scroll horizontally.

↑ This page’s hierarchy

Inventory Processing → Raw JSON → Right-click menu

Right-click menu

The editor supplies its standard editing commands plus Search Text.

Inventory Processing → Raw JSON → Right-click menu → Standard editing commands

Standard editing commands

Undo, Redo, Cut, Copy, Paste, Delete and Select All operate on the text editor, subject to its current selection and available edit history. These are text operations, not a general undo facility for tree operations.

Inventory Processing → Raw JSON → Right-click menu → Standard editing commands → Undo

Undo

Reverses the most recent text-editor edit when an undo step is available. It is not an application-wide undo for sorting, upgrades, node deletion or inventory organization.
