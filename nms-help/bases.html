Base Processing

Organize and inspect the base records in the loaded context.

Before you begin: load the intended save and context, keep a separate full backup, and synchronize any Raw JSON edits before sorting or manipulating nodes. This chapter describes code behavior; it is not a new in-game acceptance test.

Read the base list

Select Base Processing. The Node View represents the loaded context’s PlayerStateData.PersistentPlayerBases array. Raw JSON displays that base-array data, not the complete save or the whole BaseContext.

A base record’s summary includes its zero-based list index, galaxy name, system, Parts, and base name. Parts counts entries in that base’s Objects array. An empty name is displayed as Unnamed Freighter Base.

Expand a base to inspect its fields. The summary is a convenient label; the underlying JSON fields are the actual data.

Sort bases by galaxy, system, and name

Result: reorders the base records in app memory. It does not itself save the live NMS files.

  1. Finish any Raw JSON edits and choose Sync to Node View.
  2. Choose whether to leave Move Freighter to Top on Sort checked.
  3. Click Sort By Gal, Sys, Name.
  4. Read the completion notice and review the reordered base list before saving.

The sort compares galaxy first, then system, then Name. It rearranges complete base records rather than rebuilding their contents.

What the freighter option actually does

The checkbox starts checked. After sorting, the current code moves the first record with an empty Name to the first position. It uses the empty name as its freighter identification rule; it does not independently check the base type. Unchecking it leaves the ordinary galaxy/system/name ordering.

Reorder bases manually

Result: changes the in-app order and refreshes the related data views.

  1. Use the left mouse button to drag a complete base record onto another base record.
  2. For siblings under the same parent, dragging upward places the record before the target; dragging downward places it after the target.
  3. Review the base names and new indices after the operation, then save only when satisfied.
Keep whole base records together. Dragging individual fields or child nodes can change the JSON structure. The general drag guard checks parent data types; it is not a guarantee that an arbitrary structural change is valid for No Man’s Sky.
Advanced drop behavior

The source and target must have parents of the same stored data type. A cross-parent drop is placed after the target. An operation rejected by this guard leaves the attempted move unapplied. Use whole-record reordering for ordinary base organization.

Back up one base

Result: writes the chosen base record to a separate JSON file. This is not a full account/save-folder backup.

  1. Right-click the complete base record, rather than one of its fields.
  2. Choose Backup a Base.
  3. Choose the destination and filename in the Save File dialog; the offered filter is *.nms_base.json.
  4. Confirm saving and check the success or error notice.

The backup contains the selected base’s JSON as represented by the Node View. Synchronize recent Raw JSON changes first. The suggested filename uses the trimmed base name, or default when the name is empty. Canceling the file picker does not write the backup.

For protection of the full live save folder, see Full Live Save Backup.

Restore a base from a base backup

Result: adds the imported base record at the first position in the current base array. This is an addition, not an automatic match-and-replace operation.

  1. Right-click the top-level array node that contains the base list.
  2. Choose Restore a Base.
  3. Select a suitable base JSON backup in Restore A Base To First Position In Tree.
  4. Review the added record and its contents before saving the live file.
A duplicate is possible. Restoring a base does not automatically find and replace a base of the same name. It also does not restore the whole NMS save folder.

Use a base record exported for this purpose, not a complete save or an arbitrary JSON document. File-read or JSON errors mean you should stop and inspect the input rather than assume the restoration succeeded. Canceling can produce a “File Data May Not Exist” notice in the current implementation.

Inspect and copy nodes

Toggle Expansion 2 Levels
Collapses an expanded node, or expands a collapsed node through the helper’s configured depth. This changes the view, not save data.
Highlight In Text Box
Navigates to and highlights the corresponding line in Raw JSON. It does not synchronize, repair, or change data. If the views no longer reliably correspond, it refuses the navigation and explains why.
Copy This Node’s Text
Copies the selected node’s text representation to the clipboard. This is a selected-node operation, not an export of the complete BaseContext.

These actions appear when you right-click a node. The selected node determines the scope.

Delete a node or a selection

Result: removes selected data from the in-app structure after confirmation. Saving later makes that edited structure persistent.

  1. For one node, right-click it and choose Delete Node.
  2. For a range, hold the right mouse button and drag over the visible nodes; release to show Delete N Nodes.
  3. Check the highlighted selection and confirmation carefully. Cancel if it includes anything unintended.
  4. After confirming, inspect the refreshed list and Raw JSON before saving.
Deletion applies to the selected nodes. A child-field selection is not equivalent to selecting a complete base. No dedicated undo feature is documented in this edition; keep a backup and do not rely on a text editor’s Undo to reverse a tree operation.

Raw JSON controls on this tab

Sync to Node View
Parses the current text, updates the model, and rebuilds the node view. Use this after direct text editing.
Pretty Print
Parses the current text into the model, reloads formatted text, and updates the tree. It is not merely a cosmetic operation on unsynchronized text.
Import from Clipboard
After overwrite confirmation, replaces this tab’s text from the clipboard and synchronizes it. Supply the base-array JSON appropriate to this pane.
Export to Clipboard
Copies all current text from this tab’s Raw JSON pane. It does not write a save file.
Search Text
Available from the Raw JSON right-click menu; opens forward/backward text search.

The main-window Import 'BaseContext' Json from Clipboard control has a different scope: it is not the same as importing this tab’s base array. See clipboard scope.

Common questions

Why is “Restore a Base” missing?

Right-click the base-list array node. Right-clicking a base record offers Backup a Base instead; an arbitrary child field is neither of those targets.

Why is a base unexpectedly first after sorting?

Check Move Freighter to Top on Sort. The implementation moves the first empty-name record to the beginning after the ordinary sort.

Why will highlighting not work?

The node-to-text guard requires the existing node structure and displayed JSON to correspond. Resolve your intended edits and synchronize deliberately; the highlight action will not choose a data source for you.

Did sorting or restoring save my game?

No. Those actions edit app data. File → Save NMS Save File is the separate live-save action, and its confirmation and selected target matter.
