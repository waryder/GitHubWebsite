Review & Coverage

A visible boundary between this draft and the finished manual.

What is ready for review

  1. A responsive top-level index with links back from every page.
  2. A detailed Base Processing guide, including task steps, options, context menus, limitations, and disk-versus-app effects.
  3. Shared workspace and clipboard explanations.
  4. A current top-level menu reference and context-menu inventory.
  5. Local topic filtering, consistent navigation, expandable detail, and print-friendly formatting.

This is the approved first review slice. It is not represented as complete coverage of the app.

Remaining chapters and verification

  1. Opening and Saving: account/folder selection, slot metadata, Auto/Manual choice, context selection and fallback rules, load cancellation, source retention, save confirmation and consistency status.
  2. Full Backup and Manual Restore: confirmation, generated backup names, actual runtime paths, verification/results, restore instruction controls and recovery cautions.
  3. Starships: Upgrade Starships dialog, all offered types and selection states, reference matching, statistics/class/capacity/technology behavior, skips and per-ship results, preservation, empty slots, drag/reorder and deletion safeguards.
  4. Inventory Sorter: source/destination options, categories, execution, overflow and cancellation.
  5. Inventory Organizer: assignments, source shortcuts, overflow, expansion, Review Moves, Apply to app data, preview invalidation, no-op results and persisted preferences.
  6. Inventory Backup/Replacement: node eligibility, exported scope, import scope and preservation rules.
  7. Teleport Endpoints: endpoint labels, setting player location, affected fields and safety guidance.
  8. All Common Controls: exact visible labels, text-search details, keyboard shortcuts, node-selection gestures, status transitions, confirmations and errors.
  9. Troubleshooting and Glossary: task-based recovery guidance linked from the relevant error-prone operations.

How we will know coverage is complete

Each implemented visible button, checkbox, menu item, conditional right-click action, dialog option, and supported shortcut needs a linked explanation covering purpose, availability, steps, options, results and relevant cautions. Constructed-but-unplaced widgets and commented-out historical controls must not be documented as visible features.

Source inspection establishes implementation behavior. Browser checks establish that this help site works. Bill’s app/game review remains separate from both.

Useful feedback for this first edition

  1. Is the index organized the way you look for help?
  2. Is the Base Processing page easy to skim, or should any task be its own page?
  3. Are cautions visible without interrupting ordinary instructions?
  4. Do the expandable technical details provide the right depth?

Refer to the page title and section heading when requesting a change. This site contains no login, form submission, live save integration, or app-control connection.
