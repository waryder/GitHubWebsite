Review proposed inventory changes before applying them.

Use case 43 · Working with inventories

Help Index → Working with inventories → Use case 43

Use the Organizer’s private proposal to decide whether to commit inventory changes. The live route display before review is not a count of actual moves.

Before you start · Steps · Expected result · Saving · Check the result · Important details

Before you start

  1. Load the intended save and confirm its active Main or Expedition context. Make a full backup before changing data.
  2. Before sync, formatting or structured refresh, copy EACH pending Raw JSON pane to its own external file: one sync can overwrite all others. Reapply non-inventory edits one pane at a time, syncing and comparing exact values before the next. Parse errors can leave an old tree with green status; [] is ignored, and Pretty Print can erase invalid text.
  3. Do not sync/Pretty Print Inventory Raw JSON: dictionary assignment is defective. Use Organizer for supported moves or Replace Items from Backup for supported replacement.

Steps

  1. Preserve EACH pending pane externally before refresh: one sync can overwrite the others. Reapply non-inventory edits one pane at a time, syncing and verifying exact values. Stop after parse errors even if green; [] is ignored and Pretty Print may erase invalid text. Use structured tools, never defective Inventory Raw JSON sync/Pretty Print. (control reference)
  2. If Inventory Organizer is not already open, choose Inventory Processing → Node View → Inventory Organizer before using the dialog controls below. (control reference)
  3. Click Clear and check only Exosuit. Choose Resources → Container 1; set all other five categories to Leave where they are. (control reference)
  4. Uncheck Overflow: if destination is full, overflow to other 'Container' type storages. Uncheck Expand all Destination storages to 120 cells. These choices keep the example limited to resource moves into existing cells. (control reference)
  5. Read the current routes, then click Review Moves to calculate a private candidate. Inspect Review Summary and any Parts counts. (control reference)
  6. Choose Close to reject inventory changes, or Apply to app data to publish the exact reviewed candidate. A successful Apply closes the dialog. (control reference)

Expected result

  1. Review Moves leaves loaded inventory data unchanged. Apply is enabled only if the reviewed candidate changes data.
  2. Parts means whole slot/stack records, not individual units. The Organizer does not split or merge stacks or modify their amounts.

What changes, and when to save

Review Moves changes no inventory data. Apply to app data publishes the reviewed candidate in memory, marks it modified and closes the dialog. File → Save is separate and writes the loaded save target. Organizer preferences persist even when Close cancels the proposal; neither a review nor preferences create a save backup. Compare every intended edit with its preserved copy before any live write; refreshed panes alone cannot prove preservation.

Check the result

  1. After Apply, inspect Container 1 and Exosuit in the refreshed app views. Check retained resource records and amounts before using File → Save.

Important details and recovery

  1. After review, only rows with a positive move to the assigned destination are shown. Retained-only or overflow-only rows may be hidden, so the summary is not an exhaustive audit.
  2. A capacity-only change can still enable Apply without transfer rows.
  3. Changing a source, route or optional flag invalidates the review. Changed loaded data or source identity also requires a fresh review. Close still saves preferences.
